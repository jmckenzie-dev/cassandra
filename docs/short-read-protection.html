Inside the merge, not around it.

Execution path

Seven moving parts, one lazy stream.

ResolveContext

Install only where reconciliation can create a short read.

SRP is enabled when more than one data response is reconciled, the command has a finite limit, and the query is not top-K.

  • Matching point-read digests normally bypass `DataResolver`.
  • Digest mismatch and range reads enter full-data resolution.
  • Classic SRP has no separate runtime feature flag.

Accounting model

The source and the result answer different questions.

singleResultCounter

Counts each replica before reconciliation. It understands tombstones and observes without stopping.

mergedResultCounter

Counts live reconciled output and enforces the client's total and per-partition limits.

A source that looked full while the merged counter remains underfilled is the signal that a continuation may be required.

ShortReadProtection.java:42-61 · DataLimits.java:244-264

Composition invariant

Extension first. Protection second. Counting last.

The iterator is composed in this order so the first element of every appended continuation passes through all trackers and counters.

MorePartitions.extend(source) → ShortReadPartitionsProtection.applyTo(partition) → MoreRows.extend(rows) → ShortReadRowsProtection → singleResultCounter

Reordering these transformations has caused real correctness regressions.

ShortReadProtection.java:63-82

Within one partition

Resume exclusively after the last clustering.

The row protector stores the last unfiltered clustering and constructs a new `SinglePartitionReadCommand` when the source ends before the merged limit is satisfied.

  • Skinny tables terminate at `Clustering.EMPTY`.
  • A previous underfilled retry proves natural exhaustion.
  • The command retains ordering, filters, index plan, limits, and `nowInSec`.
  • It deliberately overfetches to reduce repeated round trips.
ShortReadRowsProtection.java:76-188

Across a token range

Resume after the last partition key.

Range SRP constructs a new data range with an exclusive left boundary and the original right boundary. Every appended partition gets a fresh row protector.

Single-partition commands and index commands restricted to one partition omit this outer continuation layer.

ShortReadPartitionsProtection.java:87-179 · ShortReadProtection.java:75-80

Network semantics

One replica. No speculation. No nested repair.

The continuation targets the exact source that produced the cursor. It uses a synthetic CL.ONE plan and `NoopReadRepair`, preserves transient status, and shares the initial request deadline.

The raw response iterator is returned to the outer merge so continuation tombstones remain visible.

ReplicaPlans.java:835-873 · ShortReadPartitionsProtection.java:182-204

Output pipeline

Merge → filter → post-filter → count → discard empties.

The merged enforcing counter must see only final live rows. Counting before tombstone reconciliation or replica-filter completion would let discarded rows consume the client's limit.

unfiltered merge → reconciliation + liveness filter → RFP completion / row filter (when needed) → merged DataLimits.Counter → EmptyPartitionsDiscarder

Class constellation

The small core and its supporting cast.

Three SRP classes hold the continuation logic; their correctness depends on counters, lazy transforms, replica planning, reconciliation, and range-tombstone stream repair.

orchestrator

DataResolver

Selects SRP, snapshots participants, owns the merged counter, and coordinates merge, read repair, and RFP.

composer

ShortReadProtection

Builds the source-side transformation stack in the only safe order.

row cursor

ShortReadRowsProtection

Tracks the last clustering and resumes a source partition when reconciliation remains hungry.

range cursor + dispatch

ShortReadPartitionsProtection

Tracks the last partition and dispatches both row and partition continuation commands.

accounting

DataLimits

Defines total, per-partition, paging, DISTINCT, and GROUP BY accounting and retry limits.

lazy extension

MoreRows / MorePartitions

Append iterators only when the current source is consumed, keeping network work demand-driven.

routing

ReplicaPlans / ReadCallback

Provide exact-source routing, deadline enforcement, and normal read failure propagation.

recursion guard

NoopReadRepair

Keeps each child fetch from opening an independent nested read-repair operation.

tombstone integrity

RTBoundCloser

Closes open range-tombstone markers at limits so concatenated continuations remain valid.

Dependent mechanisms

Where SRP's contract propagates.

direct dependency

Replica Filtering Protection

RFP's first phase is lazy and SRP-protected. Rows that might be incomplete are then fetched by primary key from silent replicas, reconciled again, re-filtered, and only then counted.

  • Replica-side filtering can become stale after cross-replica reconciliation.
  • RFP may consume more of the first-phase stream after completing a candidate row.
  • A 2025 fix explicitly avoided unnecessary SRP after a satisfied single-partition limit.

Fifteen years of pressure testing

From eager loop to lazy source completion.

Immediate follow-ups fixed wrong multiget commands, result overrun, retry sizing, zero-live division, CQL3 counting, and consistency guarantees after digest mismatch.

Current worktree · static analysis

Two contracts are presently out of alignment.

The implementation wiring is confirmed. The precise user-visible failures remain to be demonstrated with focused distributed tests.

01

CASSANDRA-18424 · default disabled

Graceful tombstone paging loses completion state at the wire.

A replica stores `tombstoneLimitedRow` only on its mutable local command. `ReadResponse` carries no equivalent flag or resume position, so a remote coordinator sees an ordinary under-limit response.

replica truncates wire loses marker SRP infers exhaustion pager may end
  • An all-tombstone short page counts zero live rows, another explicit SRP stop condition.
  • Range pagers do not retain page-command objects for local marker inspection.
  • The configured numeric paging threshold currently behaves only as an enable sentinel; the cutoff uses `tombstone_failure_threshold`.
  • Matching truncated digests can bypass `DataResolver`.
Static verdict: high-confidence response-contract gap. Keep `tombstone_paging_threshold: -1` until remote completion semantics and distributed coverage exist.

02

Paxos v2 · conditional on configuration

The short-read callback is both incomplete and too late.

Paxos passes a callback because an extra ordinary replica read can invalidate a prepare's optimistic linearizability decision. Yet only partition continuation invokes it; Paxos reads are single-partition and use row continuation.

resolve returns lazy iterator Paxos checks flag CQL consumes later row SRP fires unseen

Even adding a callback to `ShortReadRowsProtection` would not solve the timing defect: `Paxos.begin()` reads the flag before the lazy merge advances any source.

Static verdict: confirmed wiring and timing defect; a barrier-controlled concurrent Paxos-v2 test is required to prove a concrete linearizability anomaly. The local default remains Paxos v1.

Change-impact map

Where to expect the next collision.

Filter the map by severity. Risk tracks how directly a change can challenge SRP's completion, cursor, or counting contracts.

critical

Alternative termination

Any scan budget, cancellation, tombstone cutoff, or partial-response mode that makes under-limit mean something other than exhaustion.

critical

DataLimits and paging

Total, per-partition, DISTINCT, GROUP BY, and page counters define every SRP trigger and stop condition.

high

Filter order

Moving liveness, tombstone, row-filter, RFP, or empty-partition stages changes what may consume the final limit.

high

Indexes and RFP

Index candidate semantics may require more than cursor append. RFP directly controls demand on an SRP stream.

high

Range cursors

Reverse order, inclusive bounds, partition transitions, skinny rows, and range tombstones determine safe progress.

high

Transactions

Paxos and Accord need child reads in the right context and cannot finalize safety before lazy continuation is known.

high

Wire and mixed versions

Every deliberate incomplete response needs explicit, versioned completion metadata and a complete resume position.

medium

Replica planning

Topology, transient status, and routing changes must preserve the exact logical source and original request deadline.

medium

Resource accounting

Repaired-data overreads, response buffering, and child read-size meters interact with repeated continuations.

For the next read-path change

A compact SRP review checklist.

Use these questions whenever a patch touches limits, filtering, paging, replica completion, or transaction routing.

  • Can a replica now stop before natural exhaustion?
  • Can the coordinator distinguish every termination reason?
  • Is the resume boundary complete for point, range, and reverse reads?
  • Are continuations exclusive and guaranteed to progress?
  • Does the source counter observe every appended row and partition?
  • Does the merged counter run only after final filtering?
  • Can per-partition draining bypass a counter or transform?
  • Are range-tombstone opens and closes balanced at boundaries?
  • Does the child retain filters, index plan, `nowInSec`, replica type, transaction context, and deadline?
  • Does outer read repair see continuations without nested repair?
  • Is transactional safety decided only after lazy resolution is known?
  • Do tests force remote, local, mixed-version, and non-replica coordinators?

The durable mental model

SRP is a lazy source-completion layer embedded inside reconciliation.
