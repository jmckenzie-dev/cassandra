Paging Across Tombstones

The user-visible pressure point

A dense delete run ended the query.

Cassandra keeps tombstones in the unfiltered replica stream because reconciliation may need them to suppress older data from another replica. A large scan therefore carries a real memory and latency cost at the replica and coordinator.

Select the graceful path

ReadCommand.executeLocally passes the configured integer into metrics recording. Exact value -1 retains TOE behavior.

Count raw tombstone-bearing content

Dead cells, qualifying row deletions, and range tombstone markers contribute before the row filter and replica DataLimits run.

Stop after one complete row item

StoppingTransformation returns the currently processed item and then ends the row iterator. MetricRecording.applyToRow stores the whole row.

Close stream boundaries

RTBoundCloser keeps the unfiltered stream structurally valid when a stopping transformation closes an iterator inside an open range tombstone.

Translate replica state into pager state

AbstractQueryPager.Pager.onClose finds the stopping row on retained page commands, records its clustering, preserves remaining live-row counts, and keeps the pager open.

Resume exclusively

SinglePartitionReadCommand.forPaging starts after the saved clustering. The next request can cross the tombstone run without returning a row twice.

An empty page with a continuation is legal in the pager abstraction. Driver behavior now determines whether the client advances automatically, exposes the empty page, or applies its own time and request budget.

State scopes

Tombstones set the cursor. Live rows set the limit.

The feature joins two accounting domains. Replica tombstone counting chooses a safe break point. Pager row counting tracks the live result contract visible to CQL.

Row granularity

One cell can stop a whole row

Each dead cell contributes independently. The iterator finishes and records the complete row, preserving any live cells in the same logical row.

Range markers

A marker is never the cursor

An over-threshold bound or boundary logs and continues. A later ordinary row that contributes a tombstone can signal the stop. A fully live row does not call the stopping counter.

Query budget

Each command starts at zero

The tombstone count belongs to one replica command. Client pages and coordinator continuation commands each receive a fresh count.

Local system keyspaces remain exempt from tombstone thresholds. Failure metrics continue to increment after the threshold for every later counted tombstone in a scan that has not yet found an ordinary stopping row.

Current branch · static analysis

The local cursor path is real. Its completion contract stops at process boundaries.

These findings follow directly from source wiring. User-visible distributed outcomes remain candidates for focused runtime reproducers.

01
Verified wiring

The stopping row is local object state.

ReadCommand.tombstoneLimitedRow stays on the mutable command that executed at the replica. ReadResponse.Serializer writes digest data, repaired-data metadata, and result bytes. It writes no field that identifies a graceful stop or designates a clustering as its resume cursor.

A remote coordinator receives a valid-looking under-limit result with no explicit continuation signal.

02
High-confidence inference

Single-partition local paging is the only integrated pager path.

SinglePartitionPager populates pageQueries for later marker inspection. PartitionRangeQueryPager creates page commands without retaining them. A range command can stop one partition iterator and continue with later partitions.

The current range cursor can advance beyond an omitted suffix of the stopped partition.

03
Verified execution path

Non-paged replica reads also select graceful stopping.

The default ReadCommand.executeLocally overload reads the global setting. Replica handlers use that overload. A request that bypasses protocol paging has no AbstractQueryPager available to consume the stopping row.

04
High-confidence inference

Long-lived local pagers retain prior page commands.

pageQueries is append-only and Pager.onClose scans from the first entry. Reusing one pager across many fetches can rediscover an earlier stopping row. Internal pager consumers deserve a focused regression test around repeated empty pages.

Committer review guide

Evidence needed for a complete paging contract.

The feature needs the same completion semantics across local and remote execution, point and range reads, protocol pages, coordinator continuations, and mixed-version clusters.

  • Define the public meaning and valid range of tombstone_paging_threshold.
  • Carry an explicit stopping reason and complete resume position across ReadResponse.
  • Prove that a remote coordinator can issue the next page after an empty stopped response.
  • Keep ordinary non-paged reads on a complete-result contract.
  • Integrate partition-range paging with an interior-partition stop cursor.
  • Exercise ascending and descending clustering order through independent query builders.
  • Exercise range tombstone open, boundary, and close positions around every stop.
  • Verify collection rows with mixed live and dead cells at the stopping threshold.
  • Apply feature settings and versions in every mixed-configuration test fixture.
  • Assert page counts, empty-page progress, request bounds, warnings, and metrics.
  • Test matching digest, digest mismatch, read repair, and transient replica paths.
  • Combine graceful stopping with SRP row and partition continuation.
Durable model

A deliberate partial response needs an explicit completion state.

A cursor identifies where work may resume. A completion state explains why work stopped. Cassandra needs both pieces anywhere an under-limit response can still have live rows or reconciliation tombstones beyond its current boundary.
