Limits, Tombstones, and Completion

This branch brings two read-path mechanisms into the same execution path. Short Read Protection completes finite multi-replica results after reconciliation. CASSANDRA-18424 lets a replica stop a dense tombstone scan and carry its progress into another page. Their intersection turns replica completion state into a distributed correctness requirement.

FEATURE / 01

Short Read Protection

A coordinator-side source-completion layer inside reconciliation. It fetches more rows or partitions from the same replica when tombstones and filtering leave the merged result underfilled.

Paging across tombstones

An opt-in replica checkpoint at the tombstone failure threshold. It records a stopping row and lets a local single-partition pager continue after that clustering.

Feature 01 · coordinator

SRP fills a result that reconciliation made short.

A replica can satisfy its own finite command and still contribute too few final rows. Newer tombstones, liveness, row filtering, and replica filtering can remove candidates during merge.

Core trigger

A full source and a hungry merge

SRP compares a per-source counter with a merged-result counter. A source that appeared to fill its limit can receive a continuation when the merged counter still needs rows.

source A count = requested count merged live count < client limit → resume source A → merge appended unfiltered content → filter and count again
Core invariants

Same source, same pipeline, one deadline

  • Resume exclusively after the last observed row or partition.
  • Target the replica that owns the cursor.
  • Keep continuation tombstones visible to outer reconciliation.
  • Apply the final counter after reconciliation and filtering.
  • Share the original request deadline across child reads.
Activation: current DataResolver installs SRP for finite, non-top-K resolution with more than one participating response. Matching point-read digests commonly bypass full-data resolution.

Feature 02 · replica and pager

CASSANDRA-18424 turns TOE into a page checkpoint.

Commit 95ba53bcc81666d32b3353b03bf351ec47fda10b keeps legacy failure behavior as the default and introduces a configured graceful path.

Default

-1 keeps TOE

The new feature is disabled by default, preserving the parent branch's failure behavior.

Current setting model

Any other integer enables

The configured field acts as a sentinel. The actual cutoff count still comes from tombstone_failure_threshold.

Page result

Zero live rows is valid

A page can contain no live rows and still carry progress through a local PagingState.RowMark.

Feature 03 · response boundary

The branch adds a completion state without a wire field.

The local pager can inspect the same command object that stopped. A remote coordinator sees serialized result bytes from a different command object in the replica process.

Historical SRP inference

Under-limit retry means source exhaustion.

ShortReadRowsProtection records how many rows it requested and how many the source returned. A later extension ends when lastFetched < lastQueried.

New replica behavior

Under-limit can mean checkpoint.

A graceful scan can stop before later live rows or later reconciliation tombstones. The response serializer carries no stop reason and no field designating a tombstone cursor.

ReadCommand.java:730-780 · ReadResponse.java:359-401
Current static conclusion: a remote graceful stop can satisfy SRP's natural-exhaustion shape with content still present on that source. This creates a credible short-result path and a credible reconciliation gap. Focused distributed reproducers are required for runtime confirmation.
Needed contract

Completion reason plus a complete source cursor

A final design needs versioned response metadata that identifies deliberate interruption, carries direction-aware resume state, and lets SRP continue the same source under the original request deadline before final result counting.
